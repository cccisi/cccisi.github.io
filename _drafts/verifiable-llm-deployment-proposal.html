Open Research Proposal · 2026

Continuous Model Identity Attestation
for Distributed LLM Serving

Zhaohui Chen · Hardware Security / Cryptographic Engineering · Alibaba Group
Research question. Can an independent verifier obtain fresh, auditable evidence that a distributed inference service keeps the declared model and adapters resident while serving requests, without materially degrading throughput or tail latency? We propose an attested, sampling-based measurement plane that runs alongside inference. The claim is probabilistic runtime model integrity, not a proof that every output was computed correctly.

Motivation and gap

Platform attestation establishes a trusted starting environment, but a serving model may be sharded, swapped, quantized, or extended with adapters after launch [1]. Static artifact signatures establish provenance at rest; they do not by themselves show which bytes remain in GPU memory during a request. A useful deployment claim must bind an approved artifact manifest, the serving runtime, the actual loaded shards, a fresh challenge, and a defined measurement window.

Proposed system

1 · Canonical model commitment. The model publisher signs a manifest over exact deployed tensor bytes, dtype, quantization parameters, tensor-to-rank placement, tokenizer, and runtime configuration. Each tensor is split into fixed-size pages and committed with a domain-separated Merkle tree. Each tensor-parallel / pipeline-parallel / expert-parallel rank builds its local subtree; a small authenticated reduction combines rank roots into a global model root. Host-resident experts have their own tier and transfer epoch.
2 · Inference-interleaved audits. An attested controller derives unpredictable page challenges from a verifier nonce after the serving epoch is fixed. GPU kernels hash selected resident pages during idle or low-pressure windows and return Merkle openings. A signed receipt binds the model root, challenged rank/page IDs, coverage, runtime measurement, nonce, and request/epoch identifier. Sampling frequency adapts to measured latency headroom; no zero-overhead claim is assumed.
3 · Mutable inference state. On a cache hit, record the selected prefix-cache block keys and a digest of sampled content, with tenant salt and a request-scoped commitment rather than raw prompts. This extends vLLM's existing token/parent-hash indexing [2], which identifies cache entries but does not authenticate their stored KV bytes. For dynamically loaded LoRA adapters, verify a publisher signature and bind adapter digest, base-model compatibility, and load epoch to the same receipt [3].
4 · Trust boundary. The controller and signing key run inside an attested confidential workload; CPU/GPU evidence is checked before signing [1]. A production guarantee requires the measured runtime to prevent an untrusted host or driver from bypassing audit kernels or swapping pages between measurement and use. Where this assumption is unavailable, receipts are explicitly labeled best-effort monitoring. The design must bound time-of-check/time-of-use gaps rather than hide them.

Core hypothesis

Hierarchical roots reduce cross-rank communication to small commitments; challenge-based page checks avoid a full model rehash per request; workload-aware scheduling may hide part of the audit cost. These are testable hypotheses, not established throughput figures. The main novelty to evaluate is the joint, fresh binding of distributed resident weights, adapter epochs, and selected shared cache state to an independently verifiable receipt.

Research Plan · Evidence · Collaboration

Method and evaluation

Prototype. Implement a vLLM integration on a multi-GPU server, first for tensor-parallel dense models, then MoE expert placement and dynamic adapters. Compare a baseline with no audits, full periodic hashing, and independent rank-local sampling. Evaluate BLAKE3 or another implementation only after benchmarking it on target GPUs; retain SHA-256 for signed manifest interoperability if appropriate. Compare ordinary streams, CUDA Graph integration, and Green Context partitioning only where supported [4].

Measurements. Report end-to-end tokens/s, time-to-first-token, p50/p99 inter-token latency, GPU and network utilization, receipt size, verifier cost, and energy. Vary model size, TP/PP/EP degree, batch mix, prompt length, cache hit rate, audit rate, and offload frequency. Inject persistent and transient weight-page corruption, unauthorized adapter replacement, stale manifests, replayed receipts, and poisoned shared cache blocks. Publish detection probability and time-to-detection against the actual challenge schedule; disclose missed cases.

Security analysis. A persistent change to one uniformly sampled page is detected with probability equal to that page's sampling probability per independent audit; transient changes can evade checks between audits. Hashing stored weights cannot detect arbitrary arithmetic faults or prove response correctness. It may detect sampled memory corruption, including some silent data corruption, but that benefit must be measured separately. A nonce and signed epoch bind freshness; rollback prevention needs a trusted monotonic policy or external verifier state. Private prompts, weights, and KV contents remain outside public receipts.

Prior work and distinction

NVIDIA's confidential-computing stack attests platform state and gates model-key release [1]; this project asks what the resident model state is during ongoing service. vLLM already uses prefix-block hashes and warns that dynamic LoRA loading is security sensitive [2,3]. SAGE studies GPU execution attestation [5], while sampled layerwise proofs target inference-trace correctness at substantially different cost and guarantee points [6]. The proposed receipts are complementary: they certify a measured deployment state with explicit sampling coverage, not the correctness of each generated token. Sigstore-style transparency can optionally record signed model manifests without exposing model bytes [7].

Milestones and deliverables

  • M1: Threat model, canonical signed manifest, rank-local Merkle roots, and a verifier for dense TP models.
  • M2: Attested challenge/receipt path and scheduler benchmarks; quantify overhead versus detection coverage.
  • M3: MoE offload epochs, adapter provenance, and sampled prefix-cache integrity; adversarial evaluation.
